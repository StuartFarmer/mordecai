# Node SPA Implementation Plan

> **For agentic workers:** Use superpowers:executing-plans task-by-task.

**Goal:** Separate Home/Wallet views and complete browser wallet transaction tools.

**Architecture:** Hash navigation toggles persistent DOM views. A small browser
transaction client uses existing encoding/signing plus the node HTTP API; DOM
controls render reviews and receipt states without storing secrets.

**Tech stack:** Existing vanilla JS/HTML, Vite, wallet/protocol, Vitest.

**Spec:** `docs/superpowers/specs/2026-10-25-node-spa-design.md`

## Global constraints

- Preserve wallet across SPA navigation; keep keys in memory only.
- Integer amounts, fixed maximum fee of 1,000 units, native signature compatibility.
- No blind new-transaction retries after uncertain submission.
- Signed-transaction submission was explicitly requested.

## Review focus

- Stale nonce/balance or wallet changes between review and broadcast.
- Transport errors mistaken for rejected or paid transactions.
- Repeated clicks, oversized input, mismatched network and invalid signatures.
- Navigation, browser history, focus and hidden view accessibility.
- Same behavior on the standalone wallet and custom app gateways.
