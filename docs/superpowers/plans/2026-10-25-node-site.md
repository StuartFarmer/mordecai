# Simple Node Site Implementation Plan

> **For agentic workers:** Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** Serve a compact node homepage and the existing mdBook, including the migrated field guide, from one node gateway.

**Architecture:** Keep the existing HTML/CSS/JavaScript landing page and live API polling. Build mdBook into the gateway's packaged public directory and serve it at `/docs/`, with strict file lookup rather than SPA fallback. Custom frontends retain precedence.

**Tech Stack:** TypeScript, Node HTTP, static HTML/CSS/JavaScript, mdBook 0.5.2, Vitest.

**Spec:** `docs/superpowers/specs/2026-10-25-node-site-design.md`

## Global Constraints

- Tagline: P2P toolkit for a distributed world.
- Preserve live reachability, network ID, block height, latest block hash, and refresh/error behavior.
- Preserve the complete field-guide instructions and old guide links.
- No frontend framework or new application dependencies.
- The node serves `/`, `/docs/`, and `/api/`; no separate documentation server at runtime.
- Preserve `--static` custom frontend behavior.

## Review Focus

- Documentation asset URLs and nested chapter links resolve beneath `/docs/`.
- Unknown documentation paths return 404; encoded traversal cannot escape the documentation root.
- `/docs` and old guide URLs redirect correctly, including queries and existing section anchors.
- Custom frontend routes take precedence over bundled pages and redirects.
- Missing generated documentation is detectable by build and route checks rather than a false 200 response.
