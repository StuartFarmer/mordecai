# Node Faucet Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [x]`) syntax for tracking.

**Goal:** Let visitors request test CAI from an operator-funded faucet.

**Architecture:** A gateway-owned faucet signs fixed-amount transfers with the
existing Wallet and submits through NodeRpcClient. CLI configuration is opt-in;
the plain HTML form uses the same gateway's faucet endpoints.

**Tech Stack:** TypeScript, Node HTTP, existing wallet/protocol/RPC packages,
vanilla browser JavaScript, Vitest, mdBook.

**Spec:** `docs/superpowers/specs/2026-10-25-faucet-design.md`

## Global Constraints

- 10,000 base units per claim; 60-second recipient and socket-IP cooldown.
- 100 claims per hour; in-memory limits, no forwarded-header trust.
- Disabled by default; dedicated encrypted keystore and environment passphrase.
- No secrets in browser responses, logs, or public config.
- Reuse existing libraries; no new third-party dependencies.

## Review Focus

- Ambiguous RPC results must not create duplicate payouts or nonce gaps.
- Concurrent submissions must not bypass limits or reuse a pending nonce.
- Malformed JSON, oversized input, noncanonical addresses, and self-transfers.
- Empty wallets and disabled faucets must not claim successful payouts.
- Restart/proxy limitations must be explicit in operator documentation.
